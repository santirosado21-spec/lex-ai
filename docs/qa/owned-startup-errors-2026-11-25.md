# Owned reader startup: retry only connection refused

Base f6cc2f68 (PR38 response fix). Separate from the rejected process-group work.

Reproduced before this change: an inventory/attestation transport failure is retried 100 times and replaced by the generic motor startup timeout message. A 1000ms request budget can also expire before the bounded ps/lsof sequence finishes.

Only TCP ECONNREFUSED observed before connecting now gets ERR_OWNED_ENDPOINT_NOT_READY. The connected-socket verification path still maps failures to ERR_OWNED_ENDPOINT_UNVERIFIED. Owned reader startup retries only NOT_READY; other failures trigger existing cleanup immediately. The transport retains original inventory/socket errors privately as Error.cause while exposing a stable verification message, not raw inspector output. Its per-attempt request budget is 15000ms, matching the owned transport deadline, not the prior 1000ms. Legacy product runtime behavior is unchanged. No added retries after text, no shared endpoint, no fallback on verification failure.

Original Linux measurement: 36/36 focal tests and build pass. Tests include real ECONNREFUSED, live unrelated listener rejected with zero bytes, permanent inventory cause rejected after one attempt, two not-ready attempts then success, inspection taking 1150ms allowed, and persistent refusal stopping after 100 attempts with no reader request. The previous negative mutation removing the permanent-error guard fails the single-attempt test. Diff check passes. Independent Mac 37/37 with socket delta and negative mutation was reported by the reviewer before this follow-up.

Limits: The startup request loop now also has a 30000ms overall deadline, composed into each request signal. This does not bound model file verification or other preparation before the loop. Commands retain their 1500ms individual timeout and 256KiB max output; aborting HTTP does not physically cancel a ps/lsof command already running. Cancellation/tree cleanup/resource boundaries are not solved here. A reader failure still makes that instance terminal; future UI must create a new instance only after verified cleanup and preserve the document. Runtime remains off. This is not a real model startup or privacy-quality result.


Directed board follow-up: 42/42 Linux focal tests and build pass. Real owned Node socket plus actual ps and injected lsof error traverses request() and startup, exposing only the stable verification message; its leader exit is observed separately. Transport test checks exact private cause. The ECONNREFUSED code is retryable only before connect, tested with a post-connect refusal. A deterministic socket adapter replaces the reserve-close-port race in the refusal classification test. A static budget assertion detects regressions to 2000/5000ms, complementing the measured 1150ms case. Six slow five-second NOT_READY attempts terminate at the 30 second loop deadline. The original startup-error test was corrected: it never proved original lsof text was preserved end to end.

Reviewer Mac probes found delayed-accept listeners (1.5s/4s blocked event loop) and accept-then-close listeners rejected UNVERIFIED with zero bytes, while the normal control succeeded. This is intentional loss of startup tolerance, not a universal startup fix: a connected socket without owned established descriptor evidence cannot be retried permissively. No real model was run. A future UI may offer a fresh instance only after confirmed cleanup, preserving its document; this patch adds no UI and does not prove group cleanup. Phase classification, cause handling and overall request-loop deadline changed after the initial Mac tests and require directed review.
