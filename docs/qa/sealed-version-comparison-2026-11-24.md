# Comparar versiones en expediente cifrado

Capacidad de producto: el servicio general ya compara versiones con compareTexts, pero el flujo cifrado de comercio exterior solo ofrecía contraste temático de flete, regalías y acuses. El abogado no podía ver los cambios léxicos de dos versiones contractuales guardadas ahí sin salir a otro flujo/store.

Criterio previo: selección explícita de dos soportes del mismo expediente, versión A base y B revisada, altas/bajas/cambios/contexto, identidades y hashes del texto extraído visibles, límite parcial explícito y ninguna conclusión jurídica ni generación. No se supone que los archivos sean el mismo contrato ni se reemplaza el contraste temático existente.

Nuevo dispatch intake.compareVersions de esquema cerrado requiere expediente cifrado y dos IDs distintos presentes. Abre/verifica los mapas con firma/asunto actuales, conserva orden solicitado, compara localmente mediante compareTexts existente y devuelve resultado y metadata mínima. No persiste resultado ni texto fuera del vault. Auditoría guarda solo ID del asunto. Hash corresponde al texto extraído, no al binario original. No hay acciones del agente ni exportación Office añadidas.

UI en Documentos del expediente usa los selectores existentes y ofrece comparación léxica separada. Texto restituido local explícito, cambios con tachado/subrayado además de color, fuentes A/B, longitudes y hashes desplegables. Cerrar limpia resultado; cambiar selección remonta vista/aborta solicitud para no mostrar resultado anterior. Vista parcial avisa sin ocultar límite. No se muestran puntuaciones de riesgo, aprobación de firma o calidad jurídica.

Medido: antes falla por acción de piloto inexistente. Después 11 PASS entre servicio cifrado, UI real, comparación existente y soportes. Servicio real importa dos TXT con lector sintético, restaura desde vault, conserva cambio 20/30 y negación, rechaza duplicado/ajeno/campoextra, compara tras reiniciar y no deja texto claro en SQLite sellado. Otro expediente no admite IDs. Cuenta de solicitudes locales no cambia durante comparación y proveedor de nube falla si se usa. UI usa compareTexts real para fixture, verifica tachado/subrayado, limpiar, selección cambiada y alerta parcial. También respuesta HTTP fallida sin resultado anterior y respuesta tardía tras cambiar selección sin resucitar texto. Capturas 1280/390 inspeccionadas, sin overflow. Build sin errores, tests añadidos a CI portable/UI.

Límites: comparación de texto extraído, no formato/firmas/imágenes/anexos omitidos; normalización NFC/espacios preexistente puede omitir cambios tipográficos. Un traslado puede aparecer como borrado+adición. Límites de algoritmo existentes producen parcial, no revisión completa. Prueba no ejecuta modelo, no mide exactitud jurídica ni integra skills draft. No Tauri/Mac GUI completa ni egress nuevo. No se tocó el caso Qwen ni sus máscaras.
