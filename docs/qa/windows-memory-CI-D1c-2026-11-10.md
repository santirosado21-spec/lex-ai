# D1c: prueba mínima de RSS en Windows CI

Se preparó y revisó un smoke del colector real en Windows sobre un proceso Node hijo propio con8MiB sintéticos, cuatro muestras en serie y límites2s/4MiB intactos. No carga documentos, nombres/líneas de comando de procesos, runtimes de inferencia o modelos. IPC desconectado y vida máxima30s terminan la fixture; limpieza forzada, salida prematura o fallo de medición producen FAIL, sin retry o medición-cero de reemplazo. [Fuentes y estado](windows-memory-CI-D1c-2026-11-10.json).

El workflow usa únicamente el runner estándar windows-2025, guard de repositorio público antes de asignarlo, cinco minutos, contents:read y checkout fijado a SHA oficial verificado con credenciales no persistidas. Un evento push de la rama del PR y paths pertinentes, sin duplicación por PR, cron, instalaciones, cache, upload-artifact, secretos o publicaciones. Root comprobó por API que el repo sigue público. [GitHub documenta ejecución estándar pública gratuita](https://docs.github.com/en/actions/concepts/billing-and-usage); no se activan runners grandes o servicios de pago.

Builder19/19 locales, revisor independiente Sol15/15 más estructura YAML. El CLI en este Mac falla explícitamente por requerir Windowsx64, con cero muestras: no se presenta como ejecución Windows. La rama podrá iniciar el primer CI al subir este archivo revisado; resultado real se agregará separado. El [runner público es una VM de16GB](https://docs.github.com/en/actions/reference/runners/github-hosted-runners): incluso un pase no acreditaría equipo físico8GB, instalador, Tauri, inferencia o portabilidad completa.
