## F0: canal elegido y borde HTTP

[ADR 0004](../architecture/adr/0004-local-web-privacy-channel.md) elige interfaz de navegador servida desde el equipo y servicio loopback local, con futura bóveda Rust supervisada. Reutiliza el canal existente; no presupone cifrado en navegador ni permite importar documentos desde una copia pública alojada que los suba al backend. El contrato inicial admite text/plain y text/markdown; extracción, detección y correspondencias pertenecen al equipo. La aplicación activa todavía importa al SQLite anterior y no integra el detector/bóveda nuevos.

Worker Sol refuerza `server/main.mjs` mediante `server/local-http-boundary.mjs`: Host loopback exacto y puerto real, rechazo de cabeceras duplicadas y targets de proxy, Origin permitido explícito y señales de navegador, preflight limitado, autenticación bearer y tipo JSON exacto. No se amplía CORS a dominios públicos ni se eliminan controles para clientes nativos legítimos. Son controles HTTP reales, no una implementación de emparejamiento, revocación o privacidad completa.

Builder y revisión independiente: **58/58 HTTP**, con peticiones reales a servidor efímero. El revisor añadió sondas temporales de rutas codificadas, Origin/Fetch-Site contradictorios y falta de bearer; el servicio no fue invocado en los rechazos. Inspección de código eligió el canal; no se ejecutó navegador/Tauri ni una prueba de 8 GB en este corte. Referencias primarias consultadas: [Node HTTP/rawHeaders](https://nodejs.org/api/http.html), [Origin](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Origin), [Sec-Fetch-Site](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Sec-Fetch-Site).

## H4b.2a: estímulos operativos y evaluador nuevo

Archivos nuevos en `eval/privacy-v2/`, `server/privacy/operational-v2.mjs` y `scripts/eval-privacy-v2.mjs`. No se modifican protocolo, corpus, detector, procedencia o scorer v1 retirados. Se conserva la política de rangos UTF-16 y umbrales anteriores; se añade correspondencia exacta de motivo de bloqueo.

Los fixtures v2 tienen estados visibles de extracción, formato, evaluación local y fallo de procesador, separados de gold. Proyección al candidato solo de ámbito, segmentos y estímulos operativos: ni IDs de examen, etiquetas, spans, preservación o esperado se envían. Es un contrato offline de fixtures; esos campos declarativos no son autoridad de importación ni permiso de egreso en producción. No se confunde un flag de prueba con un detector real.

Doce casos de desarrollo y 26 pruebas nuevas: errores de esquema/accessors/prototipos/símbolos sin ejecutar hooks, límites de 7.000 UTF-16 sumando paths/texto, 256 segmentos y 32.768 bytes de entrada, prioridades de bloqueo, separación de gold, razones incorrectas y all-blocked. Se reutiliza el matching/estadística v1 con normalización local explícita para métricas, después de validar el contrato v2, sin modificar el original.

La validación añadida de corpus comprueba separación de IDs/plantillas/textos entre splits, mínimos y tamaño preregistrado de **300 casos retenidos**. El manifiesto se valida contra bytes reales de protocolo/guía/dev/heldout, nombres exactos y UTF-8 estricto; rechaza hashes obsoletos, BOM y JSONL truncado. Esto demuestra integridad/estructura, no independencia de autor ni calidad. El nuevo examen se encarga solo tras revisión y freeze del protocolo; no se puntúa hasta congelar también candidato y corpus. Ningún ejemplo v1 vuelve a ser aceptación fresca.

Builder: **61/61** combinadas v2/scorer/procedencia/detector; root: **37/37** v2/integración después de la corrección de fixture inferior. ## Fallo de suite preservado y corrección

Primera suite conjunta: **708/709**. La prueba de cancelación esperaba llegar al primer chunk; recibió `classification_denied` antes de enviar. Diagnóstico independiente: UUID hex aleatorio de un marcador puede contener 18 dígitos que el detector interpreta como CLABE. Se reprodujo determinísticamente el mecanismo; el valor aleatorio concreto del fallo histórico no se guardó y no se reconstruye.

Se precargó el fixture con namespace e IDs deterministas sin esa secuencia, usando `importSnapshot` existente y versiones de mapa separadas por asunto. Se mantienen detector/procedencia/puerta reales y assertions de cancelación, un envío y cero resultados mostrados/guardados. Otra regresión usa un namespace con secuencia numérica y exige denegación, detecciones positivas y **cero envíos/callbacks/resultados**. No se eximen cadenas con aspecto de marcador ni se cambia su codificación de producción para esconder el problema. Es una incompatibilidad real conservada para futuras decisiones de formato.

Worker: **70/70** integración/HTTP. Root final: **721/721**, build TypeScript/Vite correcto; logs inicial/final separados en `artifacts/phased-completion-20261109-batch1/`. La denegación temprana es conservadora y sigue siendo resultado esperado del caso numérico; no se rebaja el control de privacidad para que una prueba pase.
