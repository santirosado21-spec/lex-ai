# D0: tres opciones de descarga en la landing

La landing existente ahora muestra Mac Apple Silicon, Mac Intel y Windows con catálogos independientes. Cada botón exige versión, URL del repositorio de descargas aprobado, extensión/arquitectura correctas, tamaño positivo y SHA-256. Un activo inválido deshabilita sólo su tarjeta. Intel y Windows quedan pendientes sin href; no se reutiliza el binario ARM. [Evidencia y hashes](landing-downloads-D0-2026-11-10.json).

Se verificó por metadatos GitHub el único activo utilizable: [0.4.3 ARM experimental](https://github.com/santirosado21-spec/lex-ai-descargas/releases/tag/v0.4.3), 401.541.849 bytes, SHA-256 `85526589575ed0ba6e4a267523e06d52fa8edf2d48895fd728d7995a7d1734e4`. No se volvió a descargar el archivo de 401 MB. Es el motor local anterior; la UI explica que no incluye el nuevo flujo híbrido. No hay paquetes Intel o Windows publicados, ni validación física de 8 GB o notarización de Apple acreditada.

Cuatro pruebas Node y dieciséis combinadas con D1a pasan. Playwright real pasó a 1440/1024/768/390/320 px: tarjetas, teclado, copiado, catálogos inválidos/abortados, URLs inseguras, versión/arquitectura, XSS y ausencia de overflow. Las fixtures que habilitan Intel/Windows sólo prueban las rutas; no descargan instaladores. Cero excepciones JS, HTTP fallidos, terceros o solicitudes de binarios. El aborto deliberado del catálogo se cuenta por separado.

La revisión visual de root detectó que una captura de sección conservaba scroll/foco y dibujaba la cabecera sobre la tarjeta; navegación real y nuevas capturas viewport aclaran ese artefacto. También se corrigió un defecto real: el enlace de salto enfocado quedaba detrás de la cabecera (z-index 10 frente a 20, ahora 30). Un smoke inicial de 320 px falló cuando el propio enlace enfocado interceptaba el click; se conserva. El definitivo usa Tab normal para salir y CTA real, sin blur artificial. Título y descarga enfocada quedan visibles bajo la cabecera en 320/390 px. Revisor Sol aprobó el cambio y la evidencia, sin afirmar haber repetido navegador.

Este corte prepara código y evidencia en PR #1; no desplegó la landing ni creó otro proyecto. D1/D2 conservan empaquetado, pruebas reales y publicación por plataforma. Ningún documento de cliente se cargó al sitio.
