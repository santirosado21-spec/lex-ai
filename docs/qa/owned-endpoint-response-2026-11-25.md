# Owned HTTP response callback must reject, never throw asynchronously

Reproduced on Linux with a harmless owned Node HTTP server: status 204 constructs Response with a Buffer in the end callback, which throws outside the request Promise executor. The request remains unsettled and the TypeError escapes as uncaughtException. Status 700 also causes Response to throw (RangeError).

The response end handler now wraps Response construction and rejects on constructor failure. HEAD and HTTP 204/205/304 use a null body, matching Response semantics. No attestation, ownership, shutdown, timeout or activation behavior changes.

Measured: 27/27 focal tests, build and diff check pass. New real-owned-server test covers 204, 205, 304, HEAD, invalid status 700 rejection, and a later normal 200 request. Restoring only the original end callback fails with uncaughtException at 204. Linux only; no new Mac run, no model, private input, shared port, external API or runtime activation. The rejected process-group patch is absent.

Security review follow-up: real HTTP 205 with Content-Length 5, headers sent but no body/end, and HTTP 200 with an incomplete advertised body both reject TimeoutError at the existing 15 second request deadline. The deadline includes full response consumption, not only headers. Both run concurrently; a following normal request succeeds. Exact response bound 262144 succeeds, 262145 rejects, and next request remains healthy. The status fixture now rejects startup on error/exit or a 3 second readiness deadline and removes all readiness listeners. Combined 29/29 pass. Mutating the byte cutoff to 262145 fails its boundary assertion; extending the deadline to 60 seconds fails the test's 19 second deadline. No additional app change was needed for these reviewed risks; new changes are tests/fixture/readiness only.

Final review: size overflow now has code ERR_OWNED_RESPONSE_LIMIT, so the boundary test cannot pass on an unrelated inventory or connection error. A complete 205 with five advertised bytes resolves with null body and discards those bytes, explicitly tested as the Fetch-compatible bodyless contract, not protocol validation. Deadline stays 15000ms in production; test scheduling margin is now 30000ms elapsed ceiling / 35000ms test / 45000ms fixture, without extending production time. The earlier 19 second timeout mutation is historical evidence against the earlier test; current margin still rejects a 60 second production mutation. 29/29 and build pass again.


Muse follow-up: 31/31 Linux focal tests pass. A static production-deadline assertion now pins 15000 in addition to the real full-body timeout test and its scheduler margin. Changing production to 20000 fails immediately. Raw TCP probe verifies a complete 205 actually carries five bytes on the wire, then owned transport returns null body. A raw 205 carrying 262145 bytes rejects ERR_OWNED_RESPONSE_LIMIT before conversion, intentionally preserving the global ingress byte cap even for forbidden protocol bodies; a subsequent normal request succeeds. Bodyless conversion is not a promise to accept unlimited malicious bytes. Promise reject and listener removal are idempotent; destroy can emit a second terminal event without changing settlement. node:test observed no uncaught events in these tests, but exhaustive socket/listener leak instrumentation and negative tests of every fixture readiness branch remain outside this fix. Independent Mac response tests and three mutations were reported by the reviewer (r117); the earlier Linux-only note describes the author's original measurement, not current absence of Mac evidence. No model/runtime activation.
