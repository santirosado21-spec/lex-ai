# H5b.1a — Viabilidad nativa SQLCipher y contrato DAO parcial

Fecha: 2026-11-09, rama del [PR #1](https://github.com/santirosado21-spec/lex-ai/pull/1). **Viabilidad aislada aprobada; paridad H5b.1 y H5 completos pendientes.** El almacén activo de LEX AI sigue sin cifrado.

## Implementado y medido

Worker `build_vault_h5b1`, configurado explícitamente `gpt-6-astra`, recibió el código crítico nativo. Crate separado `crates/lex-vault/`, sin importación en producto o entrada IPC/binario. Fábrica exclusivamente temporal sintética, root 0700/base 0600, conexión privada, APIs de dominio con scope exacto y revisión CAS. Importa original+registro+chunks+FTS atómicamente. `threadId:null` es ámbito sin hilo concreto, no wildcard ni autorización del llamador. No SQL libre, shell, `.db` o ruta de usuario.

Dependencias fijadas por Cargo.lock: rusqlite 0.41.1, libsqlite3-sys 0.39.1, sqlcipher-src 419.0.6. Observado: **SQLCipher 4.19.0 Community, SQLite 3.53.4, CommonCrypto, FTS5, TEMP_STORE=2/runtime=2, DELETE/FK=1, Mach-O arm64**. El test enlaza frameworks del sistema, sin dependencia dinámica Homebrew/OpenSSL. APIs mantenidas generan/entregan claves; sin clave en SQL/argv/env/log. Zeroize de la asignación propia no garantiza borrar todas las copias del SO/compilador/biblioteca.

Detalles de fuentes oficiales, licencias/transitivas, comandos y límites en [README](../../crates/lex-vault/README.md). Se consultó upstream y el código descargado antes de compilar. Rustfmt faltaba: se usó archivo oficial de 1.507.584 bytes verificado contra hash del manifiesto del toolchain, extraído solo en artifacts; sin instalación global. Build inicial 6,73 s, incremental 0,23 s; fixture debug de un recorrido 213 ms. RSS 10.190.848 bytes de una corrida de **seis** tests de integración anterior a añadir el séptimo; no se extrapola al release, recovery o app entera.

## Puerta de paridad explícita

`server/privacy/vault-dao-contract.mjs` es contrato asíncrono + fixture **en memoria**, no puente nativo ni persistencia cifrada. Matriz ejecutable de **32 APIs legacy: 3 supported-core, 5 parciales, 24 no implementadas**; test falla ante método agregado/omitido. `VAULT_PARITY_COMPLETE=false`.

Pendientes: recordatorios, propuestas/decisiones/logs, tiempo/tarifas/timers/resoluciones y audit; operaciones compuestas de borradores/correo que hoy usan callbacks deben migrar a dominio atómico, no RPC sueltas. Faltan tipos/workspace enumeration con autoridad explícita, canonical wire/procedencia/manifiesto completos, equivalencia Unicode/ranking, puente IPC privado y memoria a escala de datos. Sustituir `.db` o usar varios awaits no resuelve atomicidad.

No se probó custodia Keychain, recuperación age, migración, lock de todas las conexiones/procesos, revocación/cancelación, SIGKILL/energía/disco lleno, todos los temporales Office/WAV/WebView, H3V con persistencia cifrada, empaquetado Tauri/firma/notarización o 8 GB físicos. No acceso/migración/borrado del almacén del usuario.

Siguiente: completar paridad DAO y frontera IPC conservando esta base nativa antes de H5b.2 custodia/ciclo privado/recuperación y H5b.3 migración sintética. H5b.1 sigue parcial; H5/H6 no se desbloquean por este spike.
