## Bounds and publication

The exclusive fixed leaf artifacts/privacy/nym-content-inventory-v1 uses0700; files0400. Existing leaves/symlinks/path traversal are rejected. Parent directories must already exist as real directories. Sources are opened through O_NOFOLLOW parent FDs and checked regular-file; read bounds and stable inode/size/mtime checks apply. An exclusive inventory.ndjson.partial is retained on failure; no retry/resume/overwrite. After writing, input source/freeze identities are rechecked and the entire partial's size/SHA/regular0400 state is checked before exclusive hard-link publication. Header and receipt are exclusive writes. A later failure may leave published bytes with a failed receipt; only a successful receipt and independently verified header/hash can identify a completed build. No cleanup deletion of retained failure evidence.

One30s monotonic budget and384MiB getrusage ceiling are checked after synchronous C JSON parsing, every validation/output/read loop and before publication. getrusage is process-lifetime OS high-water RSS, bytes on macOS and KiB converted on other systems. It is not a hard instantaneous memory-kill mechanism or20ms live sampler. A pathological C parse/OS call can exceed a bound before the next check; the tool then fails at the checkpoint. The receipt must report actual elapsed/peak and this scope honestly. A successful public build on this machine is not physical8GB evidence.

This shifts immutable **public build-asset generation**, not private-input processing, to a separately measured preparation stage. A future runtime loader is not implemented here and must stream bounded rows, verify exact artifact/header/source hashes, preserve all raw flags and enforce existing20ms sampling/50ms maximum gap/1GiB/60s runtime limits. No limit is raised, nor is unmeasured runtime work authorized. Public derivative data remains research-only: missing authentic full license/attribution still blocks redistribution/product release; no model quality/privacy/egress claim follows.
