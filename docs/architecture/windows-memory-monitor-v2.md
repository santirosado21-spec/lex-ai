# D1i — isolated direct WMI memory collector

The opt-in `node scripts/windows-memory-smoke.mjs --wmi` route uses a new monitor. The original one-shot default and `--persistent` route, their modules and historical evidence remain unchanged. This delivery has no Windows execution, production wiring or 8 GB acceptance. Root coordinates independent review and a later bounded CI run. PSF assigns this persistent-defect implementation to Astra; no external model consultation or dependencies were used.

D1h at c473fab/run42875919825 observed one typed WMI query for an owned PID, about5.15s total and40,656,896 working-set bytes. That supports trying the same typed access in a separate collector; it does not establish that repeated snapshots of all processes complete within2s. Earlier cmdlet-discovery stalls remain unexplained, rather than retrospectively repaired.

The fixed Windows PowerShell5.1 launcher comes from validated SystemRoot, with only SystemRoot/WINDIR environment variables, no shell/profile/PATH lookup. The command uses language syntax and .NET methods, never cmdlet discovery, New-Object, JSON cmdlets, module imports or console encoding changes. [Microsoft's5.1 type-accelerator reference](https://raw.githubusercontent.com/MicrosoftDocs/PowerShell-Docs/main/reference/5.1/Microsoft.PowerShell.Core/About/about_Type_Accelerators.md) identifies wmisearcher; [ManagementObjectSearcher.Get](https://learn.microsoft.com/en-us/dotnet/api/system.management.managementobjectsearcher.get?view=netframework-4.8.1) returns query results. [Win32_Process](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-process) specifies uint32 ProcessId/ParentProcessId and uint64 WorkingSetSize, in bytes. Documentation is API evidence, not a runner measurement. The Dispose documentation page was inaccessible in this consultation; explicit disposal follows the reviewed D1h code pattern.

A request is exactly `id:rootPid` plus LF. Regex and invariant UInt parsing reject signs, exponent notation, grouping, padding and noncanonical zeros. IDs increment exactly, the first owned root binds subsequent requests, and no query/namespace/server/credentials are received. One fixed local `SELECT ProcessId,ParentProcessId,WorkingSetSize FROM Win32_Process` runs per request. All rows are transiently inspected to reconstruct descendants; names, executable paths, command lines and other properties are not requested. Every row is disposed in finally, and nested finally blocks dispose the collection and searcher even when a previous cleanup fails. Any exception exits with finite code22 and emits no frame. Only after successful disposal does a complete numeric ASCII frame leave the child.

The parent validates frame grammar, ID/root correspondence, canonical safe integer values, row count and byte bounds before creating row objects. The frozen parser has a4MiB JSON byte bound, not a row-count limit. V2 deliberately limits4096 rows in both processes; the resulting three-field JSON is less than512KiB. Count/delimiter disagreement is rejected before split/object allocation. The existing strict parser then checks PID0 rules, duplicates, all-tree cycles, missing root, numeric overflow and sums only the root plus descendants. A zero total fails. Exceeding the row cap blocks; it never truncates. Numeric triples are not copied into persisted reports.

Startup has one absolute10s deadline beginning before spawn, covering type resolution, first query, enumeration, disposal, wire transfer and parent parsing. Four subsequent fresh samples each have one2s budget. Requests do not overlap, queue, retry or fall back. Partial output cannot renew a deadline. Boundary equality, delayed timer callbacks, slow synchronous spawn/write and late responses fail closed. Output is bounded to4MiB per response; additional/trailing frames and non-ASCII bytes fail. Owner and per-request cancellation reject pending work, clear timers/listeners and kill only the owned PowerShell process. The literal command launches no descendants; this is not a Windows Job Object or a general process-tree kill facility.

Close preserves the existing3s stdin-close wait plus3s forced-kill wait and reports whether close was actually observed. Smoke retains its owned synthetic fixture, liveness checks around awaits, four serial reads and required intentional zero exit. Its configured phase sum is5s fixture readiness +10s startup +4×2s reads +6s collector cleanup +6s fixture cleanup =35s; it is not D1h's15s diagnostic budget or a guarantee against OS scheduling delays. The fixture's existing60s self-exit remains. Cleanup failures, missing exit observations and fixture failures prevent PASS. PASS would describe this technical smoke only, never installer, model inference or physical8GB acceptance.

Local tests use injected clocks, timers and children for protocol/cleanup/deadline tests, plus the existing real Node fixture test with mocked RSS. They do not load PowerShell or run WMI on this Mac. Workflow changes retain the same public-only standard runner, permissions, jobs and diagnostic marker gates; only the ordinary RSS job selects `--wmi` and includes its new tests/files. No CI was launched from this implementation.
