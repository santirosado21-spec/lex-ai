## Decoder and composition policy

Use the pinned81-label table with40 native types; retain every native label, original offsets, token indices, confidence and artifact provenance. Finite stable softmax, unique argmax (ties block); confidence floor0.4 applies to every attended non-special token including O. Entity confidence is the minimum contributing token probability. This preserves the conservative v2 policy, not upstream0.25/recall_first or calibrated confidence. No tuning from outputs. Strict BIO: orphan I, kind-changing I, malformed transitions or non-whitespace gap bridging block; no repair, name joining or dropping low-confidence spans.

The JSON repeats the existing **unapproved** eight-type mapping proposal; all40 types remain represented. No new mapping is activated here. ACCOUNT_NUMBER/IBAN do not mean CLABE; TAX_ID does not mean RFC; GOVERNMENT_ID/SSN do not mean CURP. COMPANY_NAME, STREET_ADDRESS, DATE, URL, CITY and other unsupported types stay native/unmapped unless a later explicit mapping review changes a new frozen candidate. Native predictions are hypotheses, never legal identity validity.

Preserve compositionv2 exactly: validate every segment/span before completion. Each unmapped text span needs one internally recomputed deterministic rule wholly containing it within the same immutable source/version/hash/scope. No adjacent-rule union or cross-segment/path substitution; a model cannot supply proof authority. Coverage is literal protection of characters, not semantic relabelling. Cross-category overlaps block; same-category learned span wholly inside a rule may deduplicate while retaining the whole rule. Any path prediction blocks. Operational, provenance, UNK, confidence, BIO, offset, overflow, partial and unknown failures cannot be cured by containment. Blocked result has no detections/protection plan; valid rule diagnostics remain separate and unscored. Complete still means algorithmic completion only, with diagnosticOnly true and egressEligible false.
