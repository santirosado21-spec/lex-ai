# Nym v2: proposed original-content witness

Root proposal, 2026-11-10. This is a new structural contract requiring independent review before critical implementation. V1 remains immutable: eight witnesses, global proof false, zero neural forwards. No quality or acceptance set was scored. The paired JSON binds source research and limits; it authorizes neither implementation nor execution.

The maintained Python API returns original character offsets independently of decoding. Its configured decoder may represent an artificial Metaspace prefix as a space. Exact inverse decoding is therefore a different property from source attribution. This proposal replaces inverse equality as the sole admission authority with a stricter, explicit **original token-content witness**, while retaining inverse comparisons as diagnostics. It does not reinterpret v1 failures as passes.

The trusted implementation is the exact pinned runtime/tokenizer and Original/Char API documented in the two preserved source audits. Upstream source lookup is not a reproducible wheel-build attestation. Bounds and coverage alone do not certify alignment: conversion can fall back and byte positions can collapse. The additional witness must independently account for each token against the immutable original source, not merely trust a model-supplied offset or proof flag.

## Exact narrow path

Single original strings only; exact pinned Replace(space to U+2581), Metaspace Always/split, BOS2/A/EOS1 and decoder metadata. No caller normalization, search, trim, offset subtraction, truncation, windowing or unknown configuration. Original literal U+2581 blocks because it is ambiguous under the configured replacement. All existing control, UNK, zero/overlapping/repeated offsets and provenance failures remain blocked. No byte grouping is introduced.

Load the exact hash-verified tokenizer JSON as data to construct an immutable ID-to-raw-token inventory. Bind every used ID to that inventory and the runtime tokenizer. Do not accept an inventory or token string supplied by the model. Parent validation independently recomputes the content witness and original UTF8/UTF16 endpoints before admitting a forward or decoded result. Pure tests may inject a clearly separate tiny inventory; the real runner must enforce the fixed full tokenizer digest. Avoid retaining redundant full runtime vocabulary copies when individual used-ID checks suffice; do not raise the 1GiB cap if the implementation fails it.

Every non-special offset must be a strict integer, positive, ordered, disjoint original-codepoint interval. Build exact cumulative original UTF8 and UTF16 boundary tables; no surrogate splitting or NFC/NFD change. Require coverage of every non-whitespace scalar. Any gaps must be exact original whitespace, checked independently, and never excuse dropping an encoded token.

For proof computation only, N(slice) replaces ASCII spaces with U+2581. It does not change the source sent to the tokenizer, stored document, privacy mapping or provider envelope. Piece start is initially zero and resets only to the end of an admitted exact whitespace added token. All other added IDs are unsupported in this narrow version. Allowed whitespace entries must have special/normalized/lstrip/rstrip/single_word all false, with original slice exactly equal to pinned content. They retain their complete token/logit and provenance.

For the first ordinary BPE token of a piece, require its original start to equal the known piece start. If its original slice starts with ASCII space, its pinned raw token must equal N(slice). Otherwise it must equal exactly one U+2581 followed by N(slice). This accounts for the source-derived prepend operation at a known split boundary; it is not arbitrary prefix stripping. Preserve the whole contributing token, including the artificial representation, and mark the piece as having started. Later ordinary tokens must equal N(slice) exactly, with no virtual-prefix exception. An independently emitted prefix token that lacks this exact source-content relation remains blocked; no token is deleted or assigned an empty extent.

A recognized pinned fallback ID may represent one strict ASCII byte equal to the entire original slice, only after the first ordinary piece token. Multibyte, invalid, grouped and overlapping fallback contributions stay blocked. A literal string resembling a byte token is not authority: its actual ID and full original slice must satisfy the same checks. No voting, repairing or merging BIO transitions is permitted.

Retain every attended non-special contributor, including O, with finite 81-label rows, unique argmax, confidence at least0.4, minimum entity confidence and strict BIO. Names are not joined, unsupported types are not renamed, mappings stay unapproved and no composition/provider route is added. Native completion remains diagnostic-only and ineligible for egress.

## Bounded next experiment and limits

Use the same eight exposed structural witnesses, explicitly not an acceptance set. Before any forward, require content witnesses for indices0,1,3,4,5,6; keep emoji overlap2 and literal-control7 in the denominator and blocked. Each subsequently admitted input still needs its own witness. This is support for a narrow path, not global Unicode correctness or privacy acceptance. Inverse roundtrip/slice equality remains reported even when false; raw failures cannot be discarded. Any new failure is preserved, not patched per case.

Keep batch1/512tokens/16KiB, at most8 forwards without warmup/retry, CPU1/ORT_DISABLE_ALL, combined1GiB, total60s including1s cleanup reserve,20ms target sampling and50ms accepted-gap cap. Actual model RAM/latency remains unknown until a separate reviewed freeze/run. No scoring, development/heldout access, training, production import, active model switch or client data is authorized by this design.

Create new v2 files and fresh output/freezes; preserve v1 sources and artifacts. Independent reviewers must challenge split-boundary accounting, added tokens, fallback assumptions, forged IPC/inventory, whitespace gaps, repeated substrings, Unicode coordinates and delayed resource/deadline callbacks. Root decides after that review. This contract does not clear licenses, establish a detector's accuracy, protect a complete request or validate a physical8GB system.

## Pre-execution addendum: base BPE space runs

Static pinned metadata also lists IDs139–168 both in base BPE vocabulary and added vocabulary, with identical raw strings of2–31 U+2581 markers and all five flags false. An ID alone does not identify the extraction path. Under the global prohibition of literal original U+2581 and the audited separation of normalized:false extraction before normalization from normalized-added matching, these entries cannot match an original added-token substring. They may still be ordinary base-BPE outputs after Replace maps ASCII spaces to markers. This is a source-derived path lemma, not an observed new tokenization or an exemption for actual literal markers.

Allow only those pinned IDs when base vocabulary identity and flags match, the full original slice is exactly N ASCII spaces and the raw token exactly N markers, N2–31. Treat them as ordinary BPE tokens under the existing exact content witness; do not reset piece start or discard any contributor. All other non-whitespace added paths remain unsupported. Any failure of the source-path lemma, content relation, scope or inventory blocks. This addendum needs focused independent review before implementation; the original reviewed proposal and v1 result remain in history.
