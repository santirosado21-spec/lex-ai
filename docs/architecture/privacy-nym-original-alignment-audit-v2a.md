# Nym original alignment audit v2a — research, not approval

The maintained alignment path is a plausible **trusted API source of original spans without decoder inversion**. It carries original-byte alignments through normalization, splitting and BPE, then converts them to character offsets before returning Python encodings. Decoder equality is a different property: decoding the configured artificial marker can legitimately add a space. This finding supports a separate versioned design question; it does not authorize replacing v1 gates or establish a new offset proof. Original v1 false remains false, the saved structural run had zero neural forwards, and no tokenizer/model/source was executed in this research.

API authority means explicitly trusting a pinned implementation under stated assumptions. It is not an independent mathematical guarantee that every returned offset is correct. Range bounds, positive/disjoint intervals and coverage are necessary checks but cannot alone prove the absence of a wrong yet plausible source attribution. Root must decide the trust boundary and independent reviewer must assess it before any critical implementation or execution.

## Source findings

| Layer | Maintained source fact | Consequence / limit |
| --- | --- | --- |
| NormalizedString | Stores original and normalized strings, original_shift and one original-byte interval per normalized byte. `convert_offsets` expands a normalized alignment slice to its first original start and last original end. | Alignment is metadata maintained during transformations, not recovered by decoding/searching text. Expansion may be many-to-one; it does not guarantee disjoint tokens. |
| Exact Replace | Replace Normalizer calls NormalizedString.replace. For the selected one-original-scalar ASCII-space → one-replacement-scalar U+2581 path, the replacement's three UTF8 bytes inherit the source space's original-byte interval. | “1→1” describes scalars, not equal byte widths. The normalizer preserves original position while changing representation. Literal original U+2581 remains an explicit ambiguity block under the proposed narrow scope. |
| Virtual prefix | `prepend` replaces the first normalized character with the inserted sequence plus that character using transform_range; inserted continuation characters share prior alignment. For one prepended marker, the marker and retained first character can share that first character's source alignment. | An artificial marker does **not** necessarily get a zero-length original extent. A marker merged into an ordinary token can still have a valid covering original span; separately emitted prefix and character tokens may overlap and must remain blocked initially. No zero-length waiver, first-token discard or guessed offset subtraction. |
| Added vocabulary | Non-normalized matches are sliced first, remaining pieces normalized and normalized matches sliced next. Matches get attached tokens with local byte range0..slice length. NormalizedString.slice preserves relative alignment plus original_shift. | Added-token pieces may bypass later pretokenization. Attached tokens are retained by split, and unmatched pieces can independently receive Metaspace prefixes. No assumption of one prefix for the whole request. |
| Encoding | into_encoding converts each token's normalized-byte interval to the split's original interval, adds original_shift, then converts original bytes to chars when requested. | Decoder output is not consulted. However conversion failures can silently fall back to token.offsets / unconverted offsets. A caller cannot treat the API result as a certified successful conversion flag. |
| Byte→Char | Converter maps every byte position of each Rust char to that scalar index; the end-of-string branch returns the last mapped scalar plus one. | Interior byte positions can collapse to the same scalar coordinate. This explains a mechanism for repeated or zero character ranges; char offsets do not certify original byte-boundary validity by themselves. |
| BPE fallback | If a missing symbol can be represented by all required vocabulary byte entries, BPE appends one length1 entry per byte and later emits token offsets from the word. | Individual normalized byte tokens can map to the same original scalar. Missing fallback entries take the unknown path if configured. Overlap/zero-length/UNK remain blocked; no byte-grouping design is proposed in this audit. |

## Obligations for a narrow versioned design

A possible root design can specify original alignment as the authority and retain decoder comparisons as diagnostic observations rather than the sole source of offsets. That is a **new proof contract**, not “ignore roundtrip failures.” It requires explicit documented assumptions and independent review, including:

1. Bind exact tokenizer JSON, selected runtime/wheel identity, version, pipeline, source commit evidence and immutable original text/hash. Wheel-to-source correspondence remains limited: upstream tag/source lookup is not a reproducible build attestation. Limit the supported path to single raw original strings, with no caller pretokenization, normalization, truncation, windowing or hidden alternate tokenizer configuration.
2. Validate the entire encoding: exact BOS/EOS/special-mask/attention/ID inventory, sequence length and all contributors. Ordinary added tokens/whitespace require exact configured inventory and original-content checks; internal control, literal special, UNK and original literal U+2581 remain blocked. No attended non-special token may be dropped merely because its decoded text looks artificial or empty.
3. Require every non-special original interval to be integer, positive, in bounds, ordered and disjoint. Reject repeated, overlapping and zero ranges, including those originating from virtual prefix or byte fallback. Prove complete original scalar coverage under an explicit rule: a conservative version can require every scalar covered, including whitespace; any allowed whitespace gap would need a separate explicit exact-original-whitespace rule and still cannot hide a token. Full coverage of every scalar is a stricter research option, not an approved change to the existing non-whitespace coverage policy.
4. Build original scalar boundary tables independently: cumulative UTF8 bytes and UTF16 units. Map each returned original Char interval only by those tables; retain exact original substring and endpoint bindings across IPC. Reject surrogate splits and any inconsistent coordinate representation. The source's byte→char rounding/fallback behavior means these postconditions are not proof that no fallback occurred; trusted-path assumptions or a separate verifiable original-byte alignment cross-check remain a design obligation. Do not pretend UTF16 conversion alone establishes correct semantic attribution.
5. Preserve all-token confidence≥0.4, unique argmax/finite81-label rows and strict BIO, including O decisions. Apply original-span validation before accepting native entities; no repaired offsets, normalized-text searching, merged overlaps, token voting or byte-fallback grouping. Operational/provenance/partial/unsupported/path/overflow/unknown gates remain independent and cannot be cured by alignment success.
6. Pure mechanical source-derived examples and independently reviewed discriminating witnesses must test prefix split/merge, added-token boundaries, leading/multiple spaces, CRLF/tab, NFD, CJK, astral/ZWJ, literal marker/control and byte-looking text. Existing witnesses and denominator remain preserved; actual new tests/execution require root's separately frozen version. All old observations stay attributed to v1, never rewritten as v2 passes.

For example, source string `A` may have normalized representation `▁A`; the marker's bytes and A's bytes can map to original A's range. A **single** merged token could then point to original[0,1) even though decoding adds a space; two tokens with the same range would fail the proposed disjoint-positive requirement. These are source-derived mechanical possibilities, not observed tokenizations or entity gold. For `a😀b`, scalar endpoints0/1/2/3 correspond to UTF8 endpoints0/1/5/6 and UTF16 endpoints0/1/3/4. Returning [1,2) can denote the emoji, but repeated contributions at[1,2) remain blocked; this research does not group them.

## Conclusion boundary

Maintained Original/Char alignment can be an explicitly trusted API basis for a future narrow span contract; inverse decoding is not inherently required to recover original positions. The present evidence does **not** prove that the deployed pinned tokenizer meets all required per-input postconditions, that fallback paths are unreachable, or that trusting this API suffices for privacy authorization. Root must resolve the trust/proof gaps and independent review must approve any versioned design before Astra implements. No gate/security decision, v2 approval, execution permission, model/privacy/Spanish quality, license clearance or physical8GB claim is made here.
