# Prueba privada de Rejon.AI · Comercio exterior

Descomprime el paquete en una carpeta local de cada participante. Abre **Abrir Rejon.command** en Mac o **Abrir Rejon.cmd** en Windows con Node.js 22 con soporte de SQLite FTS5 instalado (la integración del proyecto usa 22.23.5). En Linux o Terminal ejecuta `node piloto/abrir.mjs --elegir-perfil` desde esa carpeta. Mantén abierta la terminal mientras trabajas. Si el sistema requiere instalar dependencias para su arquitectura, ejecuta `npm ci --omit=dev --ignore-scripts --no-audit --no-fund` en esa copia.

1. Elige tu perfil y el código del ejercicio. El mismo par reabre los borradores. Un código nuevo inicia un asunto independiente. Los perfiles organizan pruebas dentro de la cuenta del sistema operativo. Cada participante debe ejecutar su propia copia en su equipo.
2. En Mac puedes usar la clave principal existente del Llavero o introducir una clave temporal con entrada oculta. En Windows/Linux se usa la clave temporal. El paquete se distribuye sin credenciales. Para dar de alta el segundo ítem con Acceso a Llaveros en macOS, crea una contraseña de aplicación en tu llavero de inicio de sesión con nombre exacto **LEX AI.product.openai** y cuenta **product-api-key-lorenzo**. El ítem principal usa la cuenta **product-api-key**. La opción «alternar» cambia de cuenta en cada solicitud nueva de esa sesión. «Respaldo» recurre al segundo ítem si falla la lectura del primero antes de enviar. Un error HTTP del proveedor se muestra para que decidas cómo continuar.
3. Usa exclusivamente un asunto ficticio. Puedes escribir los campos o seleccionar **Leer documento ficticio** y elegir `piloto/factura-ficticia.txt`. La lectura automática requiere Ollama en 127.0.0.1:11434 y el modelo local `qwen3.5:2b-q4_K_M`. Si deseas instalarlo, Ollama proporciona `ollama pull qwen3.5:2b-q4_K_M`. El lanzador no hace esa descarga. Confirma los campos sugeridos y el tipo de documento.
4. Guarda. Elige la tarea de importación y lee el mensaje que recibiría OpenAI. La solicitud explícita de generación consume API de la cuenta elegida. La aplicación conserva los nombres y el texto libre en el equipo. El prompt de comercio usa el tipo documental confirmado, los marcadores y fuentes públicas. La operación, tasa, plazo o preferencia requieren revisión individual con información suficiente y la versión normativa aplicable.
5. Revisa y edita el borrador. Conserva los marcadores para la restitución. Descarga los archivos Word, Excel y PowerPoint. Abre cada uno y comprueba el cliente, el asunto, el contenido editado y las referencias.
6. Para terminar, cierra la terminal. La base de pruebas queda bajo `~/.rejon-piloto-comercio/<perfil>/<ejercicio>`, con datos restaurables en SQLite local. Esta edición se limita a ejemplos ficticios. Los artículos del índice y los nuevos PDF en cuarentena tienen estados de revisión diferentes.

El navegador se comunica con un proceso en loopback. La aplicación no publica una web ni sincroniza expedientes entre participantes. La cuota del proveedor se administra en cada cuenta. El límite de peticiones del piloto es por proceso, no por organización.

Cada generación completada guarda un recibo local en `uso-openai.jsonl` dentro del ejercicio con la cuenta seleccionada, modelo y tokens reportados. La factura y los intentos rechazados se consultan en el proveedor.
